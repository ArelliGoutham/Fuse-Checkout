# Fuse API Layer — Implementation Plan (Part 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Fastify API server with MongoDB integration, REST endpoints, auth middleware, and rate limiting for Fuse's coupons module.

**Architecture:** Fastify server with Zod validation. MongoDB repositories implement the OfferRepository interface. All routes scoped by merchant_id from API key auth. Modular monolith — modules expose service interfaces, routes call them. Composition root (`src/app.ts`) wires everything.

**Tech Stack:** Fastify, MongoDB driver, Zod, Jest + mongodb-memory-server for integration tests

  middleware/

    error-handler.ts      — maps AppError subclasses to JSON error envelope
  modules/
    offers/               — EXISTS (schemas, rules, evaluators, combo, types, index)
      routes/
        offer-routes.ts     — CRUD: POST/GET/PATCH/DELETE /api/offers
        checkout-routes.ts  — POST /api/offers/available, /validate, /apply, /apply/batch
      repositories/
        mongo-offer-repository.ts — implements OfferRepository with real MongoDB
      services/
        offer-service.ts  — factory creating OfferService + repos wired to db
    products/

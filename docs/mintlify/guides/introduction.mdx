# Introduction

OfferForge is a drop-in offers layer that sits between "customer sees price" and "customer pays" at checkout. It handles coupon validation, auto-applied offers, stacking conflicts, and analytics — so merchants don't have to build any of it.

<Tip>
  New to OfferForge? Check out the [Quickstart](/guides/quickstart) to get your first offer live in 5 minutes.
</Tip>

## What OfferForge does

<AccordionGroup>
  <Accordion title="Coupon Management">
    Create flat or percentage discounts with codes like `FLAT50`, `SAVE10`. Set min cart values, max discount caps, validity windows, and per-customer usage limits.
  </Accordion>
  <Accordion title="Auto-Applied Offers">
    Show offers automatically based on cart contents — no code needed. e.g., "10% off Electronics" appears when the cart has electronics items.
  </Accordion>
  <Accordion title="Rule Engine">
    13 composable rule types: min cart value, customer segment, first-time buyer, weekend only, category restriction, product combo, date range, and more.
  </Accordion>
  <Accordion title="Stacking & Conflict Resolution">
    Merchants define how offers combine. The engine resolves conflicts using priority, exclusive flags, and global stacking policies.
  </Accordion>
  <Accordion title="Product Catalog">
    Sync SKUs for product/category/brand-based rules. Bulk upsert via API. Define product combos for bundle rules.
  </Accordion>
  <Accordion title="Analytics">
    Track redemptions, conversions, abandonment. Measure AOV lift and revenue impact per offer.
  </Accordion>
  <Accordion title="Team Management">
    Invite team members with role-based access (owner, admin, offer_manager, analytics_viewer). Email-bound invite codes with 7-day expiry.
  </Accordion>
</AccordionGroup>

## What OfferForge is NOT

<Callout type="warning">
  OfferForge is not a payment gateway, not a checkout page, and not a coupon aggregator. We're the calculation and presentation layer between price and payment.
</Callout>

| Not this | Because |
|---|---|
| A payment gateway | We don't process transactions |
| A checkout page | Merchants already have one |
| A lending platform | We don't lend money |
| A coupon aggregator | We're embedded in checkout, not a standalone site |

## Architecture

OfferForge is built as a **modular monolith** — a single backend with strict module boundaries. Each offer type is a plugin:

```
OfferEvaluatorRegistry
  ├── CouponEvaluator      (v1 — code-based)
  ├── AutoOfferEvaluator   (v1 — cart-data-driven)
  ├── BankOfferEvaluator   (v2 — card BIN validation)
  ├── BrandOfferEvaluator  (v2 — brand-subsidized)
  └── EMIOfferEvaluator    (v3 — EMI engine)
```

New offer types slot in as new evaluators — no changes to existing code.
